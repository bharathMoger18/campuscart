(Region: ap-south-1).

Soldier 4 fetches ALL parameters in ONE command:

    --path /campuscart/ \

    --region ap-south-1

LEGEND:
  [STRING]        = Plain text. Not encrypted. Safe to see in logs.
  [SECURESTRING]  = KMS-encrypted at rest. Decrypted only when fetched with
                    --with-decryption flag by an entity that has IAM permission.
  ✅ READY        = Pre-filled with correct production value. No change needed.
  ⚠  CHANGE ME   = Has placeholder value. MUST be updated before Soldier 6 runs.

── DJANGO APPLICATION ──────────────────────────────────────────────────────────

Parameter Name       : /campuscart/DJANGO_SECRET_KEY
Type                 : [SECURESTRING]
Status               : ⚠  CHANGE ME
Current Value        : CHANGE_ME_REPLACE_WITH_50_CHAR_RANDOM_KEY_*
What to set          : A 50+ character random string. Used for session signing,
                       CSRF tokens, JWT tokens, password reset links.
                       NEVER reuse this between environments.
How to generate      :
  python3 -c "import secrets; print(secrets.token_urlsafe(50))"
  OR: openssl rand -base64 50
Update command       :
  aws ssm put-parameter \
    --name /campuscart/DJANGO_SECRET_KEY \
    --value "YOUR_GENERATED_KEY_HERE" \
    --type SecureString \
    --overwrite \
    --region ap-south-1

Parameter Name       : /campuscart/DB_PASSWORD
Type                 : [SECURESTRING]
Status               : ⚠  CHANGE ME
Current Value        : CHANGE_ME_STRONG_DB_PASSWORD_HERE
What to set          : A strong, unique password for PostgreSQL.
                       Use minimum 20 characters. Mix of letters, numbers,
                       symbols. NEVER use a password from any other system.
How to generate      :
  openssl rand -base64 24
Update command       :
  aws ssm put-parameter \
    --name /campuscart/DB_PASSWORD \
    --value "YOUR_STRONG_PASSWORD_HERE" \
    --type SecureString \
    --overwrite \
    --region ap-south-1
IMPORTANT            : This same password must be in docker-compose.yml as
                       POSTGRES_PASSWORD for the db container. Soldier 4's
                       provisioning script writes it to the .env file which
                       docker-compose reads.

───────────────────────────────────────────────────────────────────────────────

Parameter Name       : /campuscart/DB_HOST
Type                 : [STRING]
Status               : ✅ READY
Value                : db
CRITICAL NOTE        : Value is "db" — the Docker Compose service name.
                       Do NOT change to "localhost" or "127.0.0.1".
                       Django runs in the "web" container. PostgreSQL runs in
                       the "db" container. Docker's internal DNS resolves "db"
                       to the database container's private IP automatically.
                       Using "localhost" would make Django look for Postgres
                       inside its own container — it would fail immediately.

───────────────────────────────────────────────────────────────────────────────

Parameter Name       : /campuscart/DB_PORT
Type                 : [STRING]
Status               : ✅ READY
Value                : 5432
Notes                : Standard PostgreSQL port. No reason to change.

Parameter Name       : /campuscart/EMAIL_HOST_PASSWORD
Type                 : [SECURESTRING]
Status               : ⚠  CHANGE ME
Current Value        : CHANGE_ME_GMAIL_APP_PASSWORD_16CHARS
What to set          : A Gmail App Password (NOT your Gmail login password).
                       Gmail requires 2-Factor Authentication + App Password
                       for SMTP access from external applications.
How to get it        :
  1. Go to myaccount.google.com
  2. Security → 2-Step Verification → Enable it
  3. Security → App passwords → Create new → Select "Mail" → "Other"
  4. Copy the 16-character code (format: xxxx xxxx xxxx xxxx)
  5. Remove spaces when storing: xxxxxxxxxxxxxxxx
Update command       :
  aws ssm put-parameter \
    --name /campuscart/EMAIL_HOST_PASSWORD \
    --value "xxxxxxxxxxxxxxxx" \
    --type SecureString \
    --overwrite \
    --region ap-south-1

Type                 : [SECURESTRING]
Status               : ⚠  CHANGE ME
Current Value        : CHANGE_ME_sk_live_STRIPE_SECRET_KEY
What to set          : Your Stripe secret API key.

Parameter Name       : /campuscart/STRIPE_PUBLISHABLE_KEY
Type                 : [STRING]
Status               : ⚠  CHANGE ME
Current Value        : CHANGE_ME_pk_live_STRIPE_PUBLISHABLE_KEY
What to set          : Your Stripe publishable key.
                       For testing: starts with pk_test_
                       For production: starts with pk_live_
Where to get         : Stripe Dashboard → Developers → API keys → Publishable key
Why String (not Secure): The publishable key is DESIGNED to be public — it is
                          sent to the browser for Stripe.js to use. It cannot
                          be used for server-side operations that require auth.
Update command       :
  aws ssm put-parameter \
    --name /campuscart/STRIPE_PUBLISHABLE_KEY \
    --value "pk_live_..." \
    --type String \
    --overwrite \
    --region ap-south-1

───────────────────────────────────────────────────────────────────────────────

Parameter Name       : /campuscart/STRIPE_WEBHOOK_SECRET
Type                 : [SECURESTRING]
Status               : ⚠  CHANGE ME
Current Value        : CHANGE_ME_whsec_STRIPE_WEBHOOK_SECRET
What to set          : The Stripe webhook signing secret. Starts with whsec_
Where to get         :
  1. Stripe Dashboard → Developers → Webhooks → Add endpoint
  2. Endpoint URL: http://YOUR_EC2_IP/api/payments/webhook/
  3. Events to listen to: payment_intent.succeeded, payment_intent.failed,
     checkout.session.completed (or whichever your Django view handles)
  4. After creating: Reveal signing secret → copy the whsec_... value
Why it matters       : Django verifies Stripe's HMAC-SHA256 signature on every
                       webhook. Without this, anyone could POST fake payment
                       confirmations to your webhook URL and mark orders as paid.
Update command       :
  aws ssm put-parameter \
    --name /campuscart/STRIPE_WEBHOOK_SECRET \
    --value "whsec_..." \
    --type SecureString \
    --overwrite \
    --region ap-south-1

Parameter Name       : /campuscart/VAPID_EMAIL
Type                 : [STRING]
Status               : ⚠  CHANGE ME
Current Value        : mailto:CHANGE_ME_YOUR_EMAIL@domain.com
What to set          : Your contact email prefixed with "mailto:"
                       Example: mailto:bharath@example.com
                       The "mailto:" prefix is REQUIRED by the VAPID spec.

HOW TO GENERATE VAPID KEYS (for all three above):
  Method 1 — Python (recommended, matches your Django setup):
    pip install pywebpush
    python3 -c "
    from py_vapid import Vapid
    v = Vapid()
    v.generate_keys()
    print('Public Key:', v.public_key_urlsafe)
    print('Private Key:', v.private_key_urlsafe)
    "

  Method 2 — web-push CLI:
    npx web-push generate-vapid-keys

Update commands      :
  aws ssm put-parameter \
    --name /campuscart/VAPID_PUBLIC_KEY \
    --value "YOUR_VAPID_PUBLIC_KEY" \
    --type String \
    --overwrite \
    --region ap-south-1

  aws ssm put-parameter \
    --name /campuscart/VAPID_PRIVATE_KEY \
    --value "YOUR_VAPID_PRIVATE_KEY" \
    --type SecureString \
    --overwrite \
    --region ap-south-1

  aws ssm put-parameter \
    --name /campuscart/VAPID_EMAIL \
    --value "mailto:your@email.com" \
    --type String \
    --overwrite \
    --region ap-south-1
